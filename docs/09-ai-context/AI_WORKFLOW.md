# AI Workflow

本文件定义 AI 在本项目中的默认工作流。目标是让 AI 先理解、再计划、再执行、再验证，避免直接生成不可维护的代码或文档。

## 基本循环

1. 理解目标：确认用户要解决的问题、期望输出、范围和限制。
2. 收集上下文：读取 `AGENTS.md`、项目上下文、对应阶段文档和技能。
3. 拆解任务：把复杂目标拆成可验证的小步骤。
4. 执行修改：按项目现有结构、命名和规范完成变更。
5. 验证结果：运行可用检查，或说明无法验证的原因。
6. 同步文档：涉及需求、设计、测试、验收、发布或运维时更新对应文档。
7. 记录状态：留下已完成、未完成、风险和下一步。

## 阶段门槛

| 阶段 | 开始前必须具备 | 结束时必须产出 |
| --- | --- | --- |
| 需求 | 目标、用户、范围 | 编号需求、业务规则、待确认问题 |
| 设计 | 需求和约束 | 模块、接口、数据模型、风险 |
| 开发 | 需求、设计、开发规范 | 源码、测试、文档更新说明 |
| 测试 | 需求、设计、源码 | 测试方案、用例、执行结果 |
| 验收 | 需求、测试证据 | 验收结论、交付检查 |
| 运维变更 | 变更目标、影响范围 | 变更记录、验证、回滚方案 |

## 上下文控制

- 先读索引和摘要，再读具体正文。
- 不一次性读取无关目录。
- 大文件只读取相关章节。
- 冲突信息以用户最新明确说明和项目事实文档为准。
- 未确认内容写入 `TODO` 或“待确认问题”。

## 虚拟机准备与 AI 装机（MCP aizhuangji）协同门禁

当项目进入现场或测试部署阶段时，若现场服务器/虚拟机尚未就绪，需遵循以下装机协同规则：

1. **强前置依赖**：传输工具执行“安装控制台”与“初次部署”前，必须具备已就绪的目标虚拟机（系统已安装、IP 与 SSH 22 端口通信正常）；
2. **基于 Excel 清单规划装机**：当虚拟机未提供时，AI 需通过 MCP `aizhuangji` 工具（`plan_excel_install_batch` 或 `plan_records_install_batch`）解析项目导出的服务器清单 Excel，生成对应的虚拟机规划计划（含规格、目标宿主机、IP、Rocky 10.1 等配置）；
3. **IP 冲突防覆盖门禁（Ping 不通检测）**：
   - **执行装机前必须实测目标 IP 连通性**：只有在目标 IP **Ping 不通**（证明局域网内无活跃主机占用该 IP，不存在覆盖或冲突风险）时，才具备执行装机的网络前提；
   - **向用户汇报时必须显式标注**：向用户呈报装机方案时，必须包含该 IP 的 Ping 探测证据，显式标注其为“Ping 不通（无冲突）”；若 Ping 通则坚决拒绝装机并报警；
4. **用户人工审核确认红线（Human-in-the-Loop）**：
   - **禁止全自动盲目执行装机**：AI 必须首先向用户呈现装机确认表（`confirmationTable`），包括虚拟机名称、规格（CPU/内存/磁盘）、分配 IP（附带 Ping 探测标注）及安装系统；
   - **必须等待用户明确审核批准**：只有在用户输入确认（如“确认装机”、“允许执行”）后，AI 才能调用 `prepare` 和 `submit_install_job` 推进装机；
5. **装机完成后无缝接力部署**：装机完成后，目标机自动加入生产网络并开机，SSH 验证通过后，AI 即可恢复自动化链路，依次在传输工具中执行“安装控制台” -> “一键初次部署” -> “实时监控日志直至部署完成”。

## 输出要求

- 输出应清晰说明依据、变更、验证和风险。
- 涉及文件时使用具体路径。
- 不用“应该没问题”替代验证结果。
- 不把 AI 推断写成已确认事实。
