# Code Organization

本文件定义通用代码组织原则。具体语言和框架规则应补充到 `CODING_STANDARDS.md`。

## 核心原则

- 一个模块只负责一个清晰职责。
- 命名应表达业务含义。
- 输入、处理、输出要分离。
- 状态和变换要分离。
- 公共逻辑提取为可复用函数、类或模块。
- 不为未来可能性提前堆复杂抽象。

## 命名规则

| 类型 | 建议 |
| --- | --- |
| 文件 | 表达职责，如 `user_service.py`、`order_processor.ts` |
| 函数 | 使用动词或动词短语，如 `create_user`、`calculate_total` |
| 变量 | 使用名词或名词短语，如 `user_profile`、`retry_count` |
| 常量 | 使用大写下划线，如 `MAX_RETRY_COUNT` |
| 测试 | 表达行为，如 `test_create_user_rejects_invalid_email` |

## 目录职责

- `src/`：生产源码。
- `tests/`：自动化测试代码。
- `docs/03-development/`：开发规范和本地运行说明。
- `scripts/`：构建、检查、部署和辅助脚本。
- `assets/`：图片、示意图、样例资源。

## 注释规则

- 注释解释“为什么这样做”。
- 不用注释复述清晰代码。
- 临时绕过、兼容逻辑、复杂算法必须说明原因和退出条件。

## AI 修改代码时

1. 先读相关需求、设计和现有代码。
2. 尽量沿用项目已有结构。
3. 不随意搬移文件。
4. 不删除未知用途代码。
5. 代码变更后同步测试和文档。
