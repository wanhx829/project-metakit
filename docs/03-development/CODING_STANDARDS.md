# Coding Standards

## 通用原则

- 代码应清晰、可维护、可测试。
- 命名应表达业务含义。
- 避免无依据的抽象。
- 修改共享逻辑时，应补充或更新测试。
- 优先保持局部简单，避免把复杂度扩散到多个模块。
- 错误处理、日志和配置应采用统一模式。

## AI 生成代码约定

- AI 修改代码前，应阅读需求、设计、开发规范和相关测试。
- AI 不应引入项目未使用的新框架，除非需求或设计明确要求。
- AI 应优先复用已有工具、模块和命名风格。
- AI 应在最终说明中列出修改文件、验证结果和剩余风险。
