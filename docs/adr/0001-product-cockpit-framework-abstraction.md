# ADR 0001: 项目产品驾驶舱 (Product Cockpit) 框架与业务数据解耦架构

- **状态**：已接受 (Accepted)
- **提出人**：项目维护者 (User) & Antigravity (AI)
- **日期**：2026-10-22

---

## 1. 背景与诉求 (Context)

当前项目已成功跑通从“PXE 裸机装机 -> 传输工具推送 -> 运维控制台底座拉起 -> 微服务基础平台部署”的全链路场景。通过 AI 自动化驱动，已经能够完成指定功能执行与验证（如“装机一个测试环境”、“部署微服务测试平台”）。

然而，现有的控制逻辑、测试用例和文档知识深度耦合了“运维控制台与交付底座”的具体业务数据。若要将这套高效的 AI 自动化驱动能力复制到其他产品（例如：专注于微服务业务中台、工业 MES 平台、物联网 SCADA 平台等），必须避免每次推倒重来。

因此，提出**“项目产品驾驶舱”**概念，将**通用引擎框架**与**特定产品的业务数据**彻底抽离。

---

## 2. 决策 (Decision)

我们决定将自动化交付与测试系统重构为 **两层解耦架构**：

### 2.1 第一层：驾驶舱通用框架引擎 (Cockpit Framework Core)
框架引擎不绑定任何特定业务，具备以下元能力：
1. **知识吸纳与清洗引擎 (Knowledge Engine)**：
   - 接收用户输入的散落文档、Swagger/API 契约、代码工程、配置模板或人工口述业务规则；
   - 自动化清洗、消歧并结构化为统一的 PRD、设计、接口、用例与运维手册。
2. **意图解析与任务编排器 (Orchestrator)**：
   - 将用户自然语言（“测一下部署”、“执行组织架构增删改查回归”）解析为标准化任务拓扑图（DAG）。
3. **测试驱动与执行底座 (Test Runner)**：
   - 依据知识库维护测试用例，自适应计算变更影响面（增量测试 vs 全量测试）；
   - 统一调度底座工具（SSH 终端、MCP 硬件装机、HTTP/REST API 探针、浏览器自动化）执行验证。
4. **闭环报告与反馈生成器 (Audit & Reporter)**：
   - 生成带有可读指标、时延、失败抓包与日志堆栈的闭环报告，呈交用户审核。

### 2.2 第二层：可插拔产品业务数据包 (Product Domain Pack)
每个具体产品作为一个独立的数据包挂载入驾驶舱，遵循统一标准契约：
- `pack.json`：产品元数据（名称、版本、维护者、环境入口）。
- `requirements/`：真实业务需求说明书、用户旅程图。
- `api-spec/`：全量接口契约、输入输出 Schema。
- `topology/`：拓扑部署结构、端口、密码、持久化路径。
- `test-cases/`：全量与增量测试用例（包含自动化断言脚本）。

### 2.3 当前已沉淀的第一个标准数据包
- **实例标识**：`cockpit-pack-ops-platform`（运维平台项目产品数据包）
- **涵盖范围**：PXE 无人值守装机、自动化传输工具、运维控制台管控 API（188 个）、底层离线底座与中间件。

---

## 3. 后续产品演进路径 (Consequences)

1. **即插即用探索新产品**：
   - 当需要探索“微服务基础平台”时，只需挂载 `cockpit-pack-microservices-base` 数据包，驾驶舱立刻无缝变身为“基础平台驾驶舱”；
2. **人类核心角色定位**：
   - 人类负责：输入核心业务数据、把控探索边界、审核代码/配置关键变更与最终测试报告；
   - 驾驶舱负责：深度探索产品细节、补全测试用例、执行验证、汇报客观事实。
