# Test Case Review Checklist

用于评审测试用例质量。本清单基于当前已编写的 `TEST_PLAN.md` 和 `TEST_CASES.md`，执行前应由测试负责人、开发负责人和产品/需求负责人共同确认。

## 覆盖性

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| P0/P1 需求是否都有用例覆盖 | 通过 | BASE/PIPE/GOV 主功能和 PERF/SEC 非功能项均已建立场景用例 |
| 主流程是否覆盖 | 通过 | 覆盖底座选择、二进制部署、打包、中间件构建、优雅上下线、API 管控、限流熔断、灰度、第三方应用部署 |
| 异常流程是否覆盖 | 通过 | 覆盖包缺失、环境检测失败、Nacos 发布失败、Nacos 摘除失败、灰度策略冲突、部署失败等 |
| 边界值是否覆盖 | 有条件通过 | 覆盖灰度比例、磁盘阈值、限流类型等；文件大小、脚本数量、接口分页上限等仍待确认 |
| 权限和角色差异是否覆盖 | 有条件通过 | 覆盖虚拟机创建、第三方应用重启卸载、高风险策略变更；更多页面按钮级权限需结合实现补充 |
| 数据一致性是否覆盖 | 通过 | 覆盖失败不覆盖旧规则/旧版本、已发布中间件不可删除、批量部分失败保留成功项 |
| 回归风险是否覆盖 | 通过 | 覆盖旧 OS 兼容、既有业务模块构建发布、优雅开关关闭后的普通重启路径 |

## 可执行性

| 检查项 | 结论 | 说明 |
| --- | --- | --- |
| 前置条件是否清楚 | 通过 | 每条用例均包含环境、依赖或数据前置 |
| 测试数据是否明确 | 通过 | 提供 OS/架构、模块编码、接口路径、灰度版本、磁盘阈值、第三方包等示例数据 |
| 操作步骤是否可执行 | 有条件通过 | 当前按设计和预期页面编写；实际执行需根据开发完成后的入口和字段微调 |
| 预期结果是否可判断 | 通过 | 预期结果包含页面、接口、配置、日志、审计、Kubernetes 状态等可观察证据 |
| 是否依赖未准备好的环境或数据 | 有条件通过 | 多 OS/架构、KubeVirt、Nacos/Sentinel/InfluxDB、企业微信、第三方部署包需测试环境支持 |

## 质量问题

| 问题类型 | 是否存在 | 说明 |
| --- | --- | --- |
| 用例重复 | 否 | 用例按需求编号和场景拆分，未发现明显重复 |
| 用例过大，一条用例验证多个目标 | 少量存在 | 部分端到端场景包含多个联动结果，适合作为开发自测和集成测试；执行时可拆分为子检查点 |
| 预期结果模糊 | 否 | 已避免“正常显示”等不可判断表述 |
| 缺少需求关联 | 否 | 每条用例均关联 BASE/PIPE/GOV/PERF/SEC 编号 |
| 缺少优先级 | 否 | 每条用例均标注 P0/P1/P2 |
| 无法复现 | 有条件存在 | 未完成开发或环境未就绪的用例应在执行时标记“阻塞”并记录原因 |

## 评审结论

有条件通过。

当前用例可作为开发自测和测试执行基线使用。执行前需要确认以下事项：

- 磁盘预警阈值最终使用 90% 还是 95%。
- 虚拟化能力、灰度审批、第三方应用部署包规范是否纳入当前迭代。
- 性能目标的基线数据和验收阈值。
- 实际页面入口、字段文案、按钮名称和接口路径是否与设计文档保持一致。
