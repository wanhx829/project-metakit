## 2. 详细测试用例清单

### 用例 1：TC-SCN-010 微服务优雅下线并排空在途请求 (P0)
- **测试类型**：端到端场景 / 业务连续性
- **前置条件**：
  1. 测试集群内微服务 `syncplant-business-eam` 已部署且处于 Running 状态；
  2. Nacos 注册中心正常，当前实例处于 Healthy=true；
  3. XXL-Job 调度中心正常连接；
  4. 压测工具正以 100 QPS 持续向该服务发送耗时约 500ms 的业务请求。
- **操作步骤**：
  1. 在“优雅上下线”控制台，选择目标 Pod `eam-xxxx-01`，点击 `[优雅下线]`；
  2. 观察 DevOps 平台下线进度弹窗及实时日志；
  3. 观察 Nacos 控制台该实例状态变化；
  4. 观察 XXL-Job 调度器该节点执行器心跳；
  5. 压测客户端持续记录响应状态码，统计停机期间的错误数。
- **预期结果**：
  1. 平台第一步通知 Nacos 将该实例标记为 `DOWN` 或直接摘除；
  2. 注册中心摘除后，网关在 1 秒内停止向该 Pod 路由新流量；
  3. XXL-Job 执行器被暂停，不再接收新调度任务；
  4. 正在处理的存量请求正常返回 200，无任何 502/504 错误；
  5. 存量请求处理完毕后容器退出，平台提示下线成功。

### 用例 2：TC-ERR-004 Nacos 摘除失败时熔断保护不得强杀 Pod (P0)
- **测试类型**：异常容错 / 生产稳定性保护
- **前置条件**：
  1. 模拟 Nacos 服务端不可写或网络切断。
- **操作步骤**：
  1. 在控制台对目标服务发起优雅下线；
  2. 观察平台行为与 Pod 状态。
- **预期结果**：
  1. 平台在调用 Nacos 注销接口失败或超时后，立即中止下线流程；
  2. 严禁直接跳过该阶段去执行 `k8s delete pod`；
  3. 弹窗与控制台明确展示错误阶段：“[阶段1失败] Nacos服务下线超时”并返回 TraceId；
  4. 目标 Pod 保持正常对外服务，不影响业务。

---

### 用例 3：TC-SCN-016 单服务 QPS 限流配置与生效验证 (P0)
- **测试类型**：功能验证 / 集成压测
- **前置条件**：
  1. 接口 `/api/order/create` 基础 QPS 约为 500；
  2. JMeter / Locust 压测工具准备就绪。
- **操作步骤**：
  1. 进入 API 管控页面，找到 `/api/order/create`；
  2. 点击 `[配置限流]`，设置单服务 QPS = 1000，流控效果为快速失败；
  3. 点击 `[保存并发布]`；
  4. 登录 Nacos 查看 `SENTINEL_GROUP` 下对应 DataId 是否生成对应 JSON 规则；
  5. 使用压测工具以 1500 QPS 阶梯压测该接口 30 秒；
  6. 观察 API 管控指标监控面板与返回结果。
- **预期结果**：
  1. Nacos 配置成功发布且格式合规；
  2. 压测中约 1000 QPS 正常返回 200，超出约 500 QPS 立即被 Sentinel 拦截返回 HTTP 429 或限流提示；
  3. 监控看板中“通过 QPS”稳定在 1000 左右，“拒绝 QPS”记录为 500 左右；
  4. 整个过程后端无线程堆积与内存暴涨。

### 用例 4：TC-ERR-006 线程数限流模式前端及后端防错拦截 (P1)
- **测试类型**：边界 / 需求约束防呆
- **前置条件**：
  1. 打开限流配置对话框。
- **操作步骤**：
  1. 尝试选择阈值类型为“线程数”；
  2. 若前端未置灰，强行填写线程数阈值 50 并点击提交。
- **预期结果**：
  1. 前端“线程数”选项置灰不可选，鼠标悬浮提示“当前版本仅支持单服务QPS限流”；
  2. 即使绕过前端直接调用后端接口，后端校验识别 `grade=0` 立即拒绝并返回业务错误码：“暂不支持线程数限流类型”；
  3. Nacos 规则不被污染。

---

### 用例 5：TC-SCN-017 手动熔断上游异常调用源 (P0)
- **测试类型**：故障隔离 / 应急排障
- **前置条件**：
  1. 存在上游调用方 A (`syncplant-business-pdm`) 与 B (`syncplant-business-mes`) 同时调用核心服务 C (`syncplant-business-eam`)。
- **操作步骤**：
  1. 服务 C 运维人员进入“熔断配置”；
  2. 新增熔断规则：上游模块选择 `syncplant-business-pdm`，设置“禁止调用”，原因填入“版本升级临时隔离”；
  3. 保存并下发；
  4. 分别用 A 和 B 向服务 C 发起 HTTP 请求。
- **预期结果**：
  1. A 服务的请求在网关/Sentinel 处被直接拦截返回熔断错误；
  2. B 服务的请求继续正常响应，业务不受任何干扰；
  3. 操作日志完整记录操作人、上游名称、熔断时间。
