# Test Plan and Case Guide

本文件面向测试人员，说明如何输出高质量测试方案和测试用例。

## 1. 测试人员的目标

测试人员不是简单罗列操作步骤，而是要证明：

- 需求是否被正确理解。
- 系统是否满足业务目标。
- 关键路径是否可用。
- 异常、边界、权限、数据一致性是否可靠。
- 风险是否被识别、验证和记录。

## 2. 编写测试方案的步骤

1. 阅读需求文档，提取需求编号、业务规则、非功能要求和待确认问题。
2. 阅读设计文档，理解模块、接口、数据模型、权限和外部依赖。
3. 明确测试范围和不测试范围。
4. 拆分测试对象，例如页面、接口、任务、数据表、权限、配置、外部服务。
5. 按风险设计测试策略，优先覆盖核心主流程和高风险模块。
6. 明确测试环境、测试数据、准入标准和准出标准。
7. 输出风险清单和阻塞项。

## 3. 测试点拆解方法

| 维度 | 关注点 | 示例 |
| --- | --- | --- |
| 主流程 | 用户最常用、最核心的路径 | 创建订单成功 |
| 异常流程 | 输入错误、服务失败、状态不允许 | 支付失败后订单状态 |
| 边界值 | 最小值、最大值、空值、重复值 | 金额为 0、超长名称 |
| 权限 | 不同角色、未登录、越权访问 | 普通用户访问管理接口 |
| 数据一致性 | 写入、更新、删除、回滚 | 库存扣减和订单创建一致 |
| 兼容性 | 浏览器、设备、版本、协议 | 移动端表单提交 |
| 性能 | 响应时间、吞吐、并发 | 100 并发查询 |
| 安全 | 注入、敏感信息、鉴权绕过 | SQL 注入、Token 过期 |
| 可观测性 | 日志、监控、错误信息 | 失败时能定位请求 ID |

## 4. 测试用例编写规则

一条好的测试用例应满足：

- 目标单一：一条用例只验证一个明确行为。
- 可执行：测试人员能按步骤执行。
- 可判断：预期结果明确，不写“正常显示”这种模糊描述。
- 可追踪：关联需求编号或缺陷编号。
- 可复现：前置条件、测试数据和环境清楚。
- 有优先级：能指导测试执行顺序。

## 5. 用例字段说明

| 字段 | 写法要求 |
| --- | --- |
| 用例编号 | 使用稳定编号，如 `TC-FUNC-001` |
| 用例标题 | 用一句话表达验证点，如“有效手机号注册成功” |
| 关联需求 | 填写 `REQ-xxx` |
| 测试类型 | 功能、接口、权限、异常、回归、性能、安全等 |
| 优先级 | P0/P1/P2/P3 |
| 前置条件 | 账号、数据、配置、环境状态 |
| 测试数据 | 明确输入值，不写“随便输入” |
| 操作步骤 | 按 1、2、3 写可执行动作 |
| 预期结果 | 写清页面、接口、数据库、消息、日志等可观察结果 |
| 实际结果 | 执行后填写 |
| 状态 | 未执行、通过、失败、阻塞、不适用 |

## 6. 用例设计技巧

### 等价类

把输入划分为有效类和无效类，每类选择代表数据。

示例：

- 有效手机号：`13800138000`
- 无效手机号：空值、10 位、12 位、含字母

### 边界值

优先测试边界附近的数据。

示例：

- 最小长度、最大长度
- 最大值、最大值 + 1
- 过期时间刚好到达

### 状态迁移

适合订单、审批、任务、流程类系统。

示例：

| 当前状态 | 操作 | 预期状态 |
| --- | --- | --- |
| 待支付 | 支付成功 | 已支付 |
| 待支付 | 取消订单 | 已取消 |
| 已取消 | 支付 | 不允许 |

### 决策表

适合多条件组合。

示例：

| 条件 A | 条件 B | 条件 C | 预期结果 |
| --- | --- | --- | --- |
| 是 | 是 | 否 | 允许 |
| 是 | 否 | 否 | 拒绝 |

### 场景法

适合端到端业务链路。

示例：

1. 用户注册。
2. 登录。
3. 创建订单。
4. 支付。
5. 查看订单状态。

## 7. 测试用例评审标准

- 是否覆盖 P0/P1 需求。
- 是否覆盖主流程、异常流程和边界值。
- 是否包含前置条件和测试数据。
- 预期结果是否可观察、可判断。
- 是否能发现真实风险，而不是只验证 happy path。
- 是否有重复、无效或无法执行的用例。
- 是否需要补充自动化测试。

## 8. AI 生成测试用例时的要求

AI 生成测试用例前应先读取：

1. `docs/01-requirements/PRODUCT_REQUIREMENTS.md`
2. `docs/01-requirements/REQUIREMENT_TRACEABILITY.md`
3. `docs/02-design/`
4. `docs/04-testing/TEST_PLAN_AND_CASE_GUIDE.md`
5. `docs/04-testing/TEST_CASES.md`

AI 输出测试用例时必须：

- 关联需求编号。
- 标注测试类型和优先级。
- 给出明确测试数据。
- 写出可执行步骤和可判断预期结果。
- 对缺失信息列出待确认问题。
